## New finding

### Major 1: the hidden note is still exposed to assistive tech through `aria-describedby`
`#motion-note` is permanently referenced by `aria-describedby` on the toggle. `visibility:hidden` does not stop a directly-referenced node from contributing to the accessible description (accname step 2B). Checked with the Chromium AX tree (`Accessibility.getFullAXTree`) against the preview with the OS NOT reducing: the button is `REDUCE MOTION | desc: "· SET BY YOUR SYSTEM"`. So every default screen-reader user hears "reduce motion, toggle button, not pressed, set by your system", which is false. This is an a11y failure (verdict rule: Blocker/Major). The Playwright test only asserts the attribute exists under OS reduce; it never checks the description is absent when the OS does not reduce.
Fix: set `aria-describedby="motion-note"` in `sync()` only while `os` is true and remove it otherwise (and do not render it in the HTML), keeping `visibility:hidden` for the layout. Add an assertion for the absent attribute in the default-project toggle test. Also consider dropping the `aria-hidden` `· ` prefix from the described text if it still appears in the description (the AX string shows the `·`; aria-hidden children are skipped in description computation only when hidden from the tree, which was not the case here because the entire note was hidden-but-referenced; re-check after the fix).
