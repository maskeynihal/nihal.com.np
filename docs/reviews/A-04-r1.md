## Findings

### Major 1: [CONFIRM]/[ASK] notes and unconfirmed fragments ship in public JS
`src/components/SoundToggle.astro` (client `<script>`, line 22) does `import { copy } from '../content/copy'`. Vite bundles the entire `copy` object into `dist/_astro/SoundToggle.astro_astro_type_script_index_0_lang.*.js`. After `pnpm build` (plain, no PUBLIC_SHOW_UNCONFIRMED), `grep CONFIRM dist/_astro/*.js` hits: the `pending` array verbatim (including "live URL returned 404 on 2026-11-05", the unconfirmed analytics sentence, the regions sentence, the "I reply within a day or two" line), plus `posterAltWithCruiser` ("toy Land Cruiser"), which is a [CONFIRM] fact. Hidden work and cv rows do not leak (`work.ts` is not in the chunk). The A-04 e2e check only scans `body.innerText`, so it misses this. It also adds roughly 3 KB to a script that was small before. Fix: client scripts import only the keys they need (for example a tiny `prefs-copy.ts`, or pass strings via `data-*` attributes from the Astro frontmatter), and move `pending` out of the `copy` object into a build-only module that no client code can reach. Add a test or e2e check that greps `dist/**/*.js` for `[CONFIRM`/`[ASK`.

### Major 2: GitHub search query is not restricted to public repos
`scripts/fetch-github.ts` queries `author:maskeynihal type:pr is:merged -user:maskeynihal`. With an unauthenticated call this gives 41 merged and 13 closed (verified). With an authenticated token that can see private org repos, the same query returned 1070 merged and 71 closed for the owner's account (verified with `gh api`). The script reads `GITHUB_TOKEN`, so running `GITHUB_TOKEN=$(gh auth token) pnpm github:fetch` locally would publish private-repo counts (and leak activity volume) on the site footer. Add `is:public` to both queries (verified: `is:public` gives 41 and 13 with and without auth). Add a unit assertion that the query string contains `is:public`.

### Ruling on closed-PR count
13 is correct. `is:unmerged is:closed -user:maskeynihal` over public repos returns 13. The profile's "18 unmerged/closed" equals `is:unmerged` public (18), which includes 5 still-open PRs (verified: `is:open` public = 5). The profile is stale/loose, not the data. Minor note for the orchestrator: profile line "18 unmerged/closed PRs" should read 13 closed plus 5 open.
