# E-11 Physics spike and budget

Date 2026-11-05. Spike code: `scripts/spike/rapier-spike.ts` (`pnpm exec tsx scripts/spike/rapier-spike.ts`). Nothing in `src/` changes.

## What was measured
`@react-three/rapier` 2.2.0 loads the engine with `import('@dimforge/rapier3d-compat')` (version 0.19.2 in the lockfile). That package inlines the 1.5 MB wasm as a base64 string inside `rapier.mjs`. The spike builds a tiny Vite 8 entry (`await import(rapier)`, `await init()`, a world with 1 static + 7 dynamic bodies, 120 steps) and measures:

- Wire size of the emitted chunk(s), gzip -9 and brotli q11.
- Cold time in Chromium 1217 (Playwright 1.64.1): median of 7 runs, fresh browser context per run (no HTTP or wasm compile cache), served from loopback so network time is excluded. Desktop is an Apple M4; "4x" is CDP `Emulation.setCPUThrottlingRate` 4, the Pixel-class proxy.

Two variants:
- `inline`: the package as shipped (what `@react-three/rapier` does today).
- `wasm`: same package, the base64 literal cut out at build time by a small Vite plugin and served as a real `.wasm` fetched at init. This stands in for the `@dimforge/rapier3d` route. `@dimforge/rapier3d` is **not installed** (only `rapier3d-compat` 0.12.0 and 0.19.2 are in `node_modules/.pnpm`), and no dependency changes are allowed, so the real package was not tried.

## Decision
Use the default `rapier3d-compat` (variant `inline`) for E-05.

- Init is not the problem: 110 ms total at 4x throttle (an earlier run on a loaded machine read 148 ms), and the chunk loads after the poster is shown and the page is idle (the shell never imports it; `check:graph` enforces that).
- Size is the only real difference: the real-`.wasm` route saves about 161 KB brotli (27%), but today it needs a build-time regex over a minified vendor bundle (pinned to 0.19.2, it throws if the literal moves) plus emitting and URL-resolving the asset. The proper fix is `@dimforge/rapier3d` with an alias, which needs a dependency change the owner has not approved.
- The physics chunk loads only on the desktop and capable-phone path after the poster is already showing, so 601 KB brotli does not touch LCP or the initial graph.

If the owner later allows the dependency change, switch to the `.wasm` variant and tighten the budget below.

## F-02 budget number
- **Physics chunk (default `rapier3d-compat`): <= 620 KB brotli** (measured 600.8 KB, about 3% headroom), <= 830 KB gzip (measured 810.0 KB).
- If the real `.wasm` route is adopted: JS <= 25 KB br, `.wasm` <= 430 KB br (total <= 455 KB br; measured 439.5 KB).
- Not in the initial graph either way; the existing `desk-vendor <= 320 KB` budget is separate from this chunk.

## Caveats
- Loopback transfer: add transfer time on the real network (601 KB at 1.6 Mbit/s is about 3 s; the `.wasm` route saves about 0.8 s there). Neither variant blocks first paint.
- 4x throttling on an M4 is a proxy, not a Pixel. F-04 owns the real-device numbers.
- Vite 8 (rolldown) with esbuild minify; Astro's final chunk may differ by a few KB.
