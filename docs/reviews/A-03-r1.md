## Pass 1: Code

### Major 1: stored `'full'` overrides the OS reduce query for `data-motion` while A-02 CSS still obeys the media query (inconsistent state)

`src/lib/prefs-inline.js` sets `data-motion=full` when `localStorage['nihal:motion']==='full'` even if `prefers-reduced-motion: reduce` matches. `src/styles/global.css` (A-02) has two caps: `[data-motion='reduce']` and an unconditional `@media (prefers-reduced-motion: reduce)` block. So a user with OS reduce who has pressed the toggle to "full" gets: `data-motion=full` (3D, physics, JS motion allowed, `canRun3D()` true) but CSS animations and transitions still killed. That is a split state: the page says "full" while half the system is reduced. It also contradicts the written specs:

- 03-implementation-spec §3: "reduce if stored **or** media query" (a union).
- 01-design-spec §9: "Reduced motion by media query **and** toggle".
- Ticket DoD: `reducedMotion: reduce` project must have the attribute present.

**Ruling: (a).** The OS preference is a floor; the toggle can only add reduction. Reasons:

1. The spec wording is a union.
2. WCAG 2.3.3 (and 2.2.2 intent) are about honouring the user's system-level request; a persisted site-level "full" survives long after a user later enables the OS setting (vestibular onset, new device profile), so a stale `localStorage` value would silently re-enable parallax-class motion against the OS request.
3. Option (b) would force deleting the media-query CSS block, so a no-JS or pre-script reader with OS reduce loses the cap. The CSS media query is the only reduction that works without JS.
4. (a) needs no CSS change. The A-02 CSS is already correct under (a).

Required behaviour, precisely:

- `effective = (stored === 'reduce' || mq.matches) ? 'reduce' : 'full'`. Stored `'full'` has no effect on the attribute. Prefer to persist only `'reduce'` and remove the key when the user un-reduces.
- Inline script: drop the `m !== 'full'` clause.
- `initPrefs` OS listener: on change, recompute `effective` from stored and the new `mq.matches`; do not bail out because a key exists.
- Toggle: when the OS says reduce, the button must be `aria-pressed="true"` and not able to switch to full. Use `disabled` (or `aria-disabled="true"` plus ignored click) and make that visible. Otherwise the button lies (pressed, click does nothing visible).
- Tests: change the inline cases `['full', true]` to `reduce`, `['bogus', true]` stays `reduce`; change the e2e `reduced-motion` project toggle test (currently flips reduce to full and expects persistence) to assert that the toggle cannot leave reduce; add a prefs.test case for OS reduce plus stored full.

### Major 2: sound toggle visible text runs together ("SOUNDOFF")

`SoundToggle.astro` renders `<span>sound</span><span data-sound-state>off</span>` with no gap; confirmed in the browser at desktop and 375 px: the label reads "SOUNDOFF" / "SOUNDON". `02-copy.md` §3 says the toggle is "sound" with state text "on"/"off", which a reader must see as two words. Add a margin/gap (for example `display:inline-flex; gap:.5em` on `.pref-toggle` or a space) and cover it with a layout check. The accessibility tree is fine (name "sound", `aria-pressed`, the `aria-hidden` state span avoids a double announcement), so this is a visual/copy-gate failure only.
